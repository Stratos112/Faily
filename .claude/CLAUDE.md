# Faily — Claude Context

## What this is
Local audio app (NiceGUI) for TTS, voice cloning, and sound effects.
Primary deployment is a Docker container (single image, two venvs — installed by `scripts/setup_linux.sh`, which the `Dockerfile` runs phase by phase) on the user's Windows 11 / RTX 5070 Ti (Blackwell) machine, GPU passed through via Docker Desktop + NVIDIA Container Toolkit. Dev happens in WSL2 at `/workspaces/projects/Faily`.

History: Faily originally ran natively on Windows (setup.bat/setup_piper.bat, removed in the Docker port). The `monotonic_align` MSVC crash saga in git history is from that era and was part of the motivation for moving to Docker; it does not reproduce on Linux.

## Running
```bash
docker compose up --build   # starts on http://localhost:7842
bash scripts/setup_linux.sh # bare-metal / dev-box install (all phases; or name phases: system main piper app data)
bash scripts/test_faily.sh  # full test run + clean shutdown (run against the container, or inside it)
```
Container restart/stop: `docker compose down` / `docker compose restart` (replaces the old Windows `taskkill`/`netstat` dance).

Volumes (persist across rebuilds): `./outputs`, `./models`, `./piper_checkpoints`, `./config`. The HuggingFace cache lives in `models/hf` (`HF_HOME`, set in `faily/__init__.py`) and Coqui's in `models/vc/coqui`, so they persist in both the dev workspace and the container. `entrypoint.sh` runs `setup_linux.sh data` — the two setup steps that write into those volume-mounted dirs (Seed-VC repo clone, Piper base checkpoint download) at container start, since anything baked into those paths at image-build time would just be shadowed by the bind mounts.

## Architecture

```
faily/
  core/
    model_manager.py   # ModelManager singleton — lazy load/cache/unload models
    characters.py      # Character storage (outputs/characters/{name}/config.json)
  modules/
    tts.py             # Bark / MMS-TTS via HF pipeline
    vc.py              # Voice cloning — BACKENDS dict, generate(), torchaudio patches
    foley.py           # AudioLDM2 SFX generation
  ui/
    app.py             # NiceGUI app entry, tabs: CLONE / TUNE / TTS / FOLEY
    components.py      # output_panel(), section_label(), show_error()
    tabs/
      vc_tab.py        # CLONE: ref audio upload, character save, voice preview
      tune_tab.py      # TUNE: character picker, expression sculpting, sub-character save
      tts_tab.py       # TTS: Bark/MMS narration, legacy clone-voice picker
      foley_tab.py     # FOLEY: SFX generation
```

## Key patterns

**Model loading** — always via `manager.load(key, loader_fn)`. Never import model libs at module level; always inside the loader lambda/function. The manager evicts least-recently-used models before a load until `FAILY_VRAM_RESERVE_GB` (default 6) is free, and retries once after unloading everything on CUDA OOM. Under WSL2/Docker Desktop the driver spills to shared system RAM instead of raising OOM, so the pre-load eviction is what actually protects performance there.

**Auth** — optional HTTP Basic auth via `FAILY_PASSWORD` (`_BasicAuth` ASGI middleware in app.py, HTTP scope only). Off by default.

**vc.py BACKENDS** — dict drives both UI dropdown and dispatch. Add a new backend by adding an entry + loader + generate function.

**Characters** — stored in `outputs/characters/{name}/`. Base characters have `ref_audio`. Sub-characters have `parent` + expression params (`backend`, `param1`, `param2`, `speed`, `style_prompt`). `get_ref_path(name)` resolves sub→parent transparently.

**torchaudio patch** — `_patch_torchaudio()` in vc.py replaces `torchaudio.load` globally with a soundfile implementation (torchcodec DLLs missing on user's Windows RTX 5070 Ti system). `_patch_ffmpeg_read()` does the same for transformers' ASR pipeline.

**Progress reporting** — functions accept `progress_ref: list[float]` and write 0.0–1.0 into it. UI polls via `ui.timer(0.15, ...)`.

## Platform notes
- Container: Ubuntu 24.04, Python 3.14 (main app venv) + Python 3.11 (piper_venv), both uv-managed (in `.python/`), PyTorch cu128, RTX 5070 Ti (Blackwell sm_120) passed through from the Windows host via Docker Desktop + NVIDIA Container Toolkit
- Main venv is 3.14 deliberately — chatterbox-tts pins `torch==2.6.0` on Python < 3.14 (no Blackwell sm_120 kernels); only on 3.14 does it accept torch>=2.9. `setup_linux.sh` re-asserts cu128 torch after all backend installs anyway. parler-tts is installed `--no-deps` (it pins transformers==4.46.1; vc.py's patches target 5.x)
- `torchaudio.load` still patched to soundfile (`_patch_torchaudio()` in vc.py) — harmless/still fine on Linux even though torchcodec is more likely to actually work here than it was on Windows
- transformers 5.x → `isin_mps_friendly` patched back onto `pytorch_utils`
- `piper_train`'s `monotonic_align` Cython extension is built from stock source on Linux (gcc) and survives real GPU training (verified 2026-09-29) — the MSVC crash was Windows-only. `scripts/patch_piper_train_monotonic_align_pure_python.py` remains as a fallback
- torchcodec: the cu128-index build (not PyPI's CUDA-13 one) + `nvidia-npp-cu12`, loaded via `_preload_npp()` in model_manager.py (the wheel has no rpath to NPP). Faily's own code avoids torchcodec anyway (soundfile everywhere; `transcribe_ref` passes decoded samples)
- Piper training status/stop: `train()` writes `outputs/characters/<name>/piper_training.json`; the training dialog and header chips poll it (`ui/tabs/piper_training_dialog.py`). "Stop early" drops `piper_train/STOP_REQUEST`, honored by a callback that `scripts/patch_piper_train_stop_request.py` injects into piper_train (saves an epoch-exact checkpoint, then stops); without the patch it falls back to SIGTERM. Learning rate: piper_train has no LR flag and Lightning restores the checkpoint's optimizer state on resume, so `scripts/patch_piper_train_learning_rate.py` adds a callback that applies `FAILY_PIPER_LR` after the restore (UI field on the TRAINING tab, persisted as `piper_learning_rate` in settings, default 5e-5; lessac's checkpoint sits at ~1.5e-4). Match options: `scripts/patch_piper_train_freeze.py` honors `FAILY_PIPER_FREEZE` (comma list of generator submodules, e.g. `enc_p,dp`); the TRAINING tab has MATCH toggles per aspect (timbre → dec/flow/enc_q, rhythm → dp, pronunciation → enc_p; `MATCH_ASPECTS` in modules/piper.py, settings `piper_match_*`, default timbre=reference, rhythm/pronunciation=base) — an aspect set to Base Model is frozen. Pre-training data checks live in `modules/qualify.py` + `ui/tabs/qualify_dialog.py` (volume / trim / transcript passes, Whisper via `modules/asr.py`; originals → `refs_original/`, deletes → `refs_trash/`); checkpoint audition rows show a Whisper pronunciation score (`modules/pronunciation.py`). Unfrozen fine-tuning on a small different-speaker set wrecks pronunciation (measured via Whisper WER on unseen sentences). Progress: Lightning prints no bar when piped, so `patch_piper_train_progress.py` writes `piper_train/progress.json` and train() polls it. Models: every saved Piper model lives in `outputs/characters/<name>/models/<id>/` (model.onnx, checkpoint.ckpt, meta.json, cached pronunciation score) — registry in `core/piper_models.py`, MODELS tab in `ui/tabs/models_panel.py`. The audition list's SAVE / SAVE & USE call `piper.promote_candidate()`; the config's `piper_model` points at the active model. Training can resume from a model's checkpoint (`resume_model`) and optionally replace it (`replace_id`); each run's settings are recorded in the status file's `run` and copied into meta.json. A pre-registry `piper.onnx` is adopted on first view (checkpoint matched by file time, base voice inferred). Import: `modules/slicer.py` splits a recording at pauses; `modules/importer.py` stages the slices in a hidden `_stage_*` character; `ui/tabs/import_dialog.py` + `qualify_dialog(staging=...)` run the qualify on them (Whisper transcript pre-filled) before `commit_stage()` adds them to a character — reachable from the CLONE tab and the REFERENCES tab. Artifact check: `modules/inflation_audit.py` runs as the NOISES check inside QUALIFY EVERYTHING for EVERY clip — noise events from the signal (unpitched sound runs: breaths/hiss/clicks, per-band excess over the steady background), first screened by Whisper hearing no words in them, then each proposed fix (mute noises between words via `process_audio(mute=...)`, edge cuts) is only offered if re-transcribing the repaired audio gives the same words (EFFECT_WER). Natural breaths in recordings start unticked. Generated clips (source=inflated) additionally get a Whisper-vs-script word diff with bisected, verified edge trims, duplicate-script and low-SNR flags, and skip the Whisper transcript "correction" (their text is the script). Same one-screen-per-clip review; edge findings merge into the TRIM section. The loss graph reads TensorBoard events from `piper_train/lightning_logs/`
- Inflation script bank: `faily/data/inflation_scripts.txt` + any `inflation_scripts_*.txt` beside it (merged by `load_script_bank()`; `scripts/check_script_bank.py [--fix]` finds duplicate lines). `inflation_scripts_more.txt` adds ~300 lines per category (4,977 lines total) so inflating one category doesn't run out/overlap. New lines: write one-per-line files per category, vet them with `scripts/check_script_lines.py CATEGORY FILE [--write]` (duplicates vs the whole bank, word-count range, allowed characters, end punctuation, numbers the aligner can read, start-sound mix, repeated openings), then assemble with `scripts/build_script_bank_file.py DIR OUT` (also catches a line claimed by two categories; safe to re-run). `sample_lines(exclude=used_inflated_lines(char))` skips lines already committed as inflated. `scripts/patch_piper_train_unique_validation.py` makes piper_train's validation split transcript-grouped, so no validation sentence also occurs in the training set
- Terminology: generated zero-shot training clips are **inflated data** (`source: "inflated"`, `modules/inflation.py`; was "padding"/"buffer"); reviewing/fixing reference clips is **qualifying** (`modules/qualify.py`, `ui/tabs/qualify_dialog.py`; was "clean up"/"spell-check"). `characters.migrate_legacy_tags()` (run at startup) converts old `source: "buffer"` tags. `vc._generate_chunked` trims each chunk's edge silence and inserts a punctuation-based pause (`_PAUSE_AFTER`) between glued chunks
- Auto-qualify (inflated data only, `modules/autoqualify.py`, AUTO-QUALIFY button in the inflation wizard's last step): spoken-form script (numbers/$/% written out via num2words) is CTC force-aligned with `facebook/wav2vec2-base-960h` (own Viterbi; model auto-downloads to `models/hf`), the clip is cut to first/last word + punctuation-sized margin, audible sound not claimed by any word is muted if short (<=0.35 s) or the clip rejected, then Whisper must hear the script. Verdicts ok/review/reject; only ok stays ticked. Recordings/imports still go through the manual qualify dialog. Tunables at the top of the module; checked on e-girl's inflated clips plus synthetic pitched moans (tail/head/attached/mid-sentence)
- Inflation line selection balances how sentences START (`inflation.START_WEIGHTS`/`start_class`/`_balanced_order`: vowel 23%, sonorant 28%, fricative 19%, "The" 10%, other th 5%, stop 15%) as far as each category's bank allows; `inflation_scripts_soft_starts.txt` adds soft-opening lines. In the wizard, ADD KEPT & REVIEW FLAGGED adds the auto-qualified clips immediately, then opens the manual qualify screen for the `review` verdicts only (rejects stay out)
- The manual qualify screen and AUTO-QUALIFY share one analysis for inflated clips (`autoqualify.analyze_clip`; `refine_audits` overwrites the screen's trim/noise findings with it, `_fold_audit_into_trim` drops the loudness-based trim when `audit["aligned"]`). Accepting a trim there applies the same smooth fades (`process_audio(fade=)`). Recordings/imports still use the older loudness/pitch detectors. Change a threshold in autoqualify.py and both screens move together
- Zero-shot reference choice: `zero_shot_reference` setting ("all" = recordings + inflated, "live" = recordings only), toggled by `components.ref_mode_toggle()` on SPEAK (EXPRESSION, ZERO SHOT) and TUNE; `get_ref_chain/build_ref_audio(live_only=)`. Inflation generation always clones from live recordings only. Split & qualify (`ui/tabs/import_dialog.py`) is reachable from CLONE, a character's REFERENCES (select a clip in the table, ⋯ menu) and the Edit tab (SPLIT & QUALIFY…); its check modes are by hand / auto-qualify then review flagged / auto-qualify only (`autoqualify.auto_qualify_stage`: Whisper transcript -> alignment -> cut; `recording=True` flags a sound between words instead of muting it)
- Seed-VC vendors its own BigVGAN; `_load_seedvc` shims its `_from_pretrained` to default proxies/resume_download (no site-packages patching)
- `FAILY_NATIVE` env var must stay unset in the container — that path launches a pywebview native window, which has no display to attach to in a headless container. Server mode (the default) is what serves the browser UI at `:7842`

- Function test suite: `.venv/bin/python scripts/test_functions.py [-v] [TestClass ...] [-k name]` (stdlib unittest, ~7 s, CPU only, no model loads or network) runs in a throwaway cwd so the real `outputs/ models/ config/` are never touched. Covers paths/migration, characters + ref chain + `build_ref_audio` caps, library import/export, cleanup, settings, piper model registry/helpers, qualify/slicer/edit audio code, importer staging, inflation sampling, spoken-form normalisation, vc helpers (model call faked), model-manager eviction, rvc DSP, auth middleware, and a stale-reference guard (SpeechT5, old `outputs/vc` paths). Run it after any change to those areas; add a test with each fix. Tests tagged `@regression(issue, fix)` guard problems already fixed (huge-reference OOM, F5 transcript bleed, Parler top_k/budget/fragments, FreeVC encoder, stage-2 wiring, cleanup symlink/protected data, 3-folder layout, …): the suite never edits anything — a failure prints what it protects and a PROPOSED fix (`--report FILE` writes it as markdown); apply fixes by hand. It found: `apply_edits` clobbering its `mono` parameter (trim-silence crashed), slicer returning nothing for dense audio, `spoken_tokens` punctuation/`B12`-style tokens, and same-second model ordering
- Zero-shot test suite: `.venv/bin/python scripts/test_zero_shot.py [cases] [--repeat N] [--keep]` generates a line per backend (xtts_v2, f5_tts, chatterbox, `long:*` for the chunked path, `parler`, `tune:*` two-stage, `vc:*` converters alone on a clean source) and checks finite/non-silent/duration plus Whisper WER; each case runs in its own subprocess. The models sample, so judge by `--repeat 3`, not one draw. Fixed with it: FreeVC's speaker encoder is downloaded by us (`_freevc_speaker_encoder`; fsspec's exists() fails on GitHub's signed redirect); Parler must be sampled with explicit `top_k=50` (transformers 5 dropped the 4.x default → mush) and gets a length-scaled token budget plus a retry when the clip is a fragment; F5 references are kept under `F5_REF_SECONDS` (11 s) because F5 itself clips at 12 s but keeps the whole transcript, so the transcript tail got spoken (`_f5_short_reference` is the backstop)

- Zero-shot reference selection: `build_ref_audio` no longer takes clips in file order. When the chain has more than `_REF_RANK_MIN_CHAIN` clips it scores an evenly spaced sample of `_REF_SAMPLE` of them with model-free measures (`_clip_features`: SNR, clipping, length, long-term spectrum similarity to the rest of the voice) and fills the budget best-first (4-10 s, clean, typical of the voice). Scores are cached per character in `ref_scores.json` (keyed by file + size + mtime); any failure falls back to file order. The budget is per backend (`characters.ref_seconds(backend)` / `REF_SECONDS`): F5 11 s, Chatterbox and XTTS 600 s (Chatterbox averages its speaker embedding over the whole reference; `vc._xtts_generate` hands XTTS a long reference as `max_ref_len` pieces via `_split_reference`, since it keeps only 10 s per file but averages embeddings across files), anything else `DEFAULT_REF_SECONDS` (30 s). Each clip's edge silence is cut to `_REF_EDGE_KEEP` before it counts against the budget, so F5's 11 s holds more speech
- TUNE/EXPRESSION stage 1 is verified: `tune_generate(verify_stage1=True)` -> `_parler_generate_checked` makes up to `PARLER_TRIES` Parler takes, Whisper-checks each against the script (stop at WER <= `PARLER_MAX_WER`, else keep the best). Parler also runs with its KV cache now (`_patch_parler_cache` restores `EncoderDecoderCache.from_legacy_cache`; ~1.7x faster, same quality)
- `python3 main.py` works from a plain shell: `main.py` re-launches itself under `.venv/bin/python` when it is not inside any virtualenv (`FAILY_NO_REEXEC=1` disables). Deferred (README TODO): real speaker-similarity scoring of generated clips

- REFERENCES hub (`ui/tabs/refs_hub.py`, data layer `core/refs.py`): the character's REFERENCES tab. ADD CLIPS / QUALIFY DATA / INFLATE DATA live here (not on TRAINING). Per clip: `active` (used when TRAINING; absent = on; the primary is always on), `clone` (the older `excluded` flag inverted: usable for zero-shot cloning), a `source` (uploaded = "" / imported = "import" / inflated; `refs.source_label`), and for inflated clips `category`/`backend`/`batch` (+ `added`) recorded at generation (`InflatedCandidate` -> `importer.stage_inflated` -> `commit_stage` -> `add_ref_clip`; older clips show backend "unknown"). Groups are a tree (`refs.group_tree`): all data > recordings > uploaded | imported, and inflated > backend > category; every node has `keys`, totals, a table `filter`. The hub shows drill-down group cards (click = scope the breakdown chart to that group, with a title; click again = step out) whose only actions are show-in-filter / add-more (inflated: opens the wizard preset to that backend+category) / delete. Also metric cards, the regroupable/rotatable chart (`refs.breakdown`: source | category | backend | batch | length | training state x clips | minutes | avg), and an AG Grid of every clip (sort, filter, inline transcript edit, click-to-play, checkbox selection + toolbar ACTIVATE / DEACTIVATE / DELETE / UNDO DELETE; ⋯ for cloning on/off, edit, split, send to Edit, split all long). `refs.delete_clips` moves audio to `refs_trash/<id>/` with an index (undoable via `restore_deleted`)
- ABOUT (`ui/tabs/about_panel.py`, logic `modules/profile.py: character_profile`): ranked "where it needs work" recommendations with jump buttons (thresholds are constants at the top of profile.py), the active voice model with its cached pronunciation score, and a DETAILS block (counts, minutes, typical/longest clip, transcript share, inflated by backend/category). No capability cards
- TRAINING tab trains on ACTIVE clips only (`piper.training_clips`). `ui/tabs/training_data_panel.py` is where activation is controlled: a gauge (10/30/60 min marks) and the groups drawn as NESTED BOXES — recordings and inflated are the big boxes, their sources/backends are smaller boxes inside, categories are tiles inside those (plain flex/CSS built from NiceGUI elements, not a chart, so every box is a real click target). Size = audio length, the coloured fill = share switched on (`tank_background`), colour = group/backend (`node_hue`); clicking any box (a tile, or a parent's header) switches that whole subtree on/off (`flip`, partial state shows an indeterminate checkbox); EVERYTHING / RECORDINGS ONLY / INFLATED ONLY presets. Over-long clips (> max(20 s, 3x the set's average)) are left out of the RUN automatically (`piper.drop_overlong_clips`, logged; nothing is edited) and flagged in the hub, which can split them. The old "TRAIN ON" setting and pre-training popup are gone
- Parked: per-group MIXES (`refs.mix_weights` / `node_shares` / `set_share` / `mix_plan` / `apply_mix`, tested in TestRefsData) are NOT wired to any UI right now — the sliders were taken off the TRAINING tab on purpose, to come back to. A mix is sibling weights: a node's share = product of weights down to it; moving a parent scales its children with it and its siblings take the rest; applying it switches clips on/off (total = as much as the scarcest group allows, optional cap, nearest whole clips, each group with a share keeps >= 1 clip)
- Data Inflation wizard saves itself (`inflation.save_session/load_session/clear_session/discard_session`, wired in `ui/tabs/inflation_dialog.py`): settings, script lines, every clip as it lands (`generate_batch(on_clip=...)`), ticks and auto-qualify verdicts go to `characters/<name>/inflation_session/session.json` (atomic write; throttled `_save_soon` while generating / ticking, `_save()` at the milestones). Opening the wizard with a saved run offers RESUME (straight to the review step with everything restored) or DISCARD & START NEW; clips already added are marked `committed` and skipped on restore; adding/discarding clears it. It is deliberately NOT under `misc/_tmp`, so "Clean up -> Scratch files" never eats it (it has its own opt-in category, "Unfinished inflation runs"). Long steps that finish after the page was lost (auto-qualify) keep their results and skip the screen update (`_ui_safe`); `ui.run(reconnect_timeout=60)` gives a stalled browser time to come back
- Layout: every two-pane tab uses `components.SPLIT_COLUMNS` (`minmax(340px, 1fr) 2fr`) and the right pane has `min-w-0 overflow-x-hidden`, so nothing forces a horizontal scrollbar

## Output dirs
```
outputs/characters/<name>/   # everything for one character: config, refs, refs_original, inflated clips,
                            #   models/, favorites/, history/ (all clips generated for them), model_try/
outputs/foley/              # SFX (no character connection yet)
outputs/misc/               # audio tied to no character: uploads/, TTS, mixes/, base_voice_samples/;
                            #   _tmp/ = scratch (staging, previews), safe to delete
```
Settings (gear) -> LIBRARY: character library import/export (`ui/tabs/library_dialog.py`; `characters.scan_library/import_characters/export_characters`): copies characters (plus the parents their variants need) between this `outputs/characters` and any other folder; `piper_model` paths in config.json are repointed on import. It copies rather than switching the live root, because audio is served from `/outputs` and modules bind `CHARACTERS_DIR` at import.
Settings -> LIBRARY -> Clean up disk (`core/cleanup.py`, `ui/tabs/cleanup_dialog.py`): checkbox categories (history, audition renders, scratch, unused models, training workspace…) scanned with sizes for any outputs folder; add a category by adding a row to `cleanup.CATEGORIES`. Nothing is pre-ticked; references/inflated/favorites/active model are not offered.
Paths live in `faily/core/paths.py`. `history_dir(char_name, ref_path)` picks where a new generation goes: the character's `history/` if it is a saved character (named, or cloned from one of their clips), else `misc/`. `migrate_legacy_layout()` (run at startup) moved the old `vc/ tts/ sfx/ edit/ mix/ …` folders into this layout, assigning loose clips to a character by filename prefix.
